YT-AGENT-AI — Reporte de Contenido

App web que analiza videos de YouTube: transcribe el audio con AssemblyAI y genera un reporte de contenido estructurado con Google Gemini. Interfaz Streamlit + API REST Django.

gemini-3.5-flash-lite POST /generate-report/ Auth + Throttling Docker

Descripción general

YT-AGENT-AI nació para traducir letras de canciones y evolucionó a un nuevo propósito: al ingresar una URL de YouTube, descarga el audio, lo transcribe y produce un reporte de contenido con 5 secciones (temas, argumento, opiniones, datos clave y conclusión).

Propósito actualURL de YouTube → descarga de audio → transcripción (AssemblyAI) → reporte estructurado (Gemini) → persistencia en PostgreSQL → Streamlit / REST.
API KeysLa clave de AssemblyAI (AAI_API_KEY) vive en el servidor vía .env. La clave de Gemini la provee cada usuario en el sidebar de Streamlit o en el payload REST (gemini_api_key); no va en el .env.

Flujo de ejecución

1
Entrada. Usuario inicia sesión (Streamlit o POST /login/) y provee URL de YouTube y su API Key de Gemini.
2
Descarga. YouTubeService obtiene título y descarga video/audio a media/ con yt-dlp.
3
Transcripción. TranscriptionService envía el audio a AssemblyAI y guarda el texto.
4
Análisis. AnalysisService fragmenta la transcripción (chunks de 8000, máx. 30000) y genera el reporte con Gemini, con fallback entre modelos por cuota.
5
Persistencia. Resultado guardado en translationPost vía Django ORM.
6
Visualización. La API responde el reporte + video_url/audio_url; Streamlit lo muestra con botones de descarga (vía HTTP con la sesión) y PDF local.

Autenticación y throttling

Usuarios Django

El superusuario se crea una vez con python manage.py createsuperuser. Los usuarios adicionales se crean en /admin/ → Users → Add user. Los mismos usuarios sirven para Streamlit (pantalla de login con authenticate()) y para la API (sesión).

Throttling DRF

rest_framework.throttling.ScopedRateThrottle como clase por defecto en ai_translation/settings.py (REST_FRAMEWORK). Cada vista declara su throttle_scope:

LoginView → scope login

Anti fuerza bruta, default 5/min.
LOGIN_THROTTLE_RATE

ContentAnalysisView → scope report

Operación costosa, default 10/hour.
REPORT_THROTTLE_RATE
Ajuste por entornoTasas en formato <n>/<s|m|h|d> vía .env, sin tocar código. Las vistas usan SessionNoCSRF (sesión Django sin exigir token CSRF) para que clientes no-navegador usen la cookie.

Variables de entorno

.env.example es la plantilla: AAI_API_KEY y DB_* requeridos; SECRET_KEY/DEBUG con default; LOGIN_THROTTLE_RATE/REPORT_THROTTLE_RATE opcionales. La API key de Gemini nunca va en el .env.

*/5 * * * * python /backend/cleanup_media.py >> /var/log/cron.log 2>&1

Preguntas frecuentes

¿Qué modelo de Gemini se usa?
Primario gemini-3.5-flash-lite (500 RPD) con cadena de fallback mapeada por cuota.

¿Por qué el reporte sale en español aunque el video sea en otro idioma?
El prompt instruye responder exclusivamente en español; no hay traducción, solo análisis.

¿Por qué falla con “video muy largo”?
La transcripción se trunca a 30000 caracteres y se procesa en chunks; si Gemini excede el timeout o la cuota diaria, se sugiere un video más corto o reintentar.

¿Para qué sirve la API key del .env si Gemini se pide en el frontend?
En el .env solo vive AAI_API_KEY (AssemblyAI), porque la transcripción nunca se pide al usuario. Gemini sí se pide por usuario.

¿Dónde está el historial Git?
Ver docs/GIT_REORGANIZATION_MANUAL.md (main reemplazada por feature/deploy, respaldo en main-old).
